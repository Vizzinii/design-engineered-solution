# 设计工程化方案（design-engineered-solution）

一个用于 Codex 的 skill：用工程化方法起草、深化或评审解决方案、投标技术方案、工程方案（含总起、概述、实施路径等章节），让方案经得起懂工程的甲方与评审追问。

## 核心理念

方案按工程化程度大致可分三层：

- **非工程化**：纯产品罗列、口号式承诺；
- **工程化叙事**：有总体设计、阶段划分、验收门、量化承诺，但机制不成体系；
- **工程的操作系统**：机制闭环——每步可验收、风险有应对、承诺可验证、全程可留痕。

本 skill 的目标是把方案从“工程化叙事”提升到“可验证、可审计”的一层。

## 功能

- **起草**：按“立总纲 → 先总体后排步骤 → 系统分解 → 逐环节四问自检 → 收束闭环”的工作流写方案；
- **深化**：把“确保、保障、实现”等承诺写成可判定、可验证的表述；
- **评审**：定位到具体段落找出浅显或不成体系之处，按严重程度排序，并按“原文 → 改后”给出修改建议。

输出遵循两条原则：

1. **不强制使用工程术语或黑话**：能用“评审通过、验收达标、演练通过、留痕可查”等自然表述，就不使用“风险登记册、需求追踪矩阵、传动轴”等术语；
2. **尊重保密与删减**：案例脱敏为“行业 + 系统类型”，不点名客户；数值承诺统一写成“按项目约定、经实测与双方确认”。

## 安装与使用

把本目录放到 Codex 的 skills 目录下，例如：

```text
~/.codex/skills/design-engineered-solution/
```

触发方式（任选其一）：

- 在对话中直接提到该 skill，如“使用 $design-engineered-solution 起草方案”；
- 或提出符合其适用场景的请求，如“把方案写深”“评审这份方案哪里浅显”“按甲方视角改方案”。

## 目录结构

```text
design-engineered-solution/
├── SKILL.md                  # 主文件：工作流、输出规则、自检清单、评审模式
├── agents/openai.yaml        # 界面元数据（显示名、短描述、默认提示词）
└── references/
    └── checklist.md          # 详细自检问题、“浅显→深度”示例、承诺分级规则
```

## 语言

skill 指令与示例均为中文，面向中文解决方案 / 投标技术方案的书写场景。
